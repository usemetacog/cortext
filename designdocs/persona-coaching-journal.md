## Vision

### 10x Check
The 10x version: cortext becomes the first tool that shows any knowledge worker — not just engineers — a map of who they said they wanted to become and who their session data says they're actually becoming. The product wizard sees a growth curve. The design engineer sees the week she crossed into "I'm writing more than I'm reading." The researcher sees that her session depth peaked in month 2 and has plateaued. Nobody else has this. Not Faros. Not GitHub Copilot. Not any developer analytics tool on the market in May 2026.

The behavioral journal is the seed: a growing record of scored sessions, matched signals, and gaps. Over time it becomes the evidence base for "who have you been lately?" — not just "what's your alignment rate?"

### Landscape context
- 59% of developers run 3+ AI tools in parallel. Nobody tracks whether they're getting better at any of them.
- AI generates 41% of code globally, but 93% use AI while only 10% see productivity gains. The bottleneck is behavioral, not access.
- Research confirms: the "Productivity Pressure Paradox" — organizations push for gains without supporting the identity-level change that enables them. cortext's persona frame is the correct intervention.
- EUREKA: no tool in the landscape asks the user who they're trying to become. This is a category gap, not a feature gap.

## Accepted Scope (added to this plan)

### Behavioral journal
- `~/.cortext/journal.jsonl`, append-only JSONL; written by `cortext --session-score` (stop-hook-only command — not shown in USAGE help), read by `computeAlignmentTrajectory` (new function in `src/analyzer.ts`)
- Missing journal = empty trajectory; malformed lines skipped silently (no crash)
- Concurrent writes safe: `appendFileSync` is atomic for single-line records on macOS/Linux
- Note: `--session-score {id}` requires a new `readSessionById(id)` in `reader.ts` (eng review D1 already tracked this as T1)

### Time-based session threshold
- Sessions under 5 minutes duration (earliest–latest `entry.timestamp` delta) are written to journal with `scored: false` — they appear in the record but are excluded from alignment rate computation. Combines with existing `minToolCallsToScore` threshold in `src/analyzer.ts`.

### First-run persona discovery banner
- Shown when `loadGoal()` returns null (same condition `runReview()` already handles). Dismissal state stored as `bannerDismissed: true` in `~/.cortext/goals.json`, written by `saveGoal()`.
- New CLI flags: `--set-persona` (calls existing `runGoalWizard()`), `--dismiss-persona` (sets banner dismissed flag)

### Top 3 exemplary sessions
- Journal-sorted top-3 sessions by alignment score, shown in Persona Alignment panel with date + matched signals
- **Gate:** only shown if journal has ≥ 5 scored entries (prevents misfiring on fresh installs before dogfood validates scoring accuracy)
- Note: this feature adds a new sub-panel to `renderer.ts`; the design doc's TUI mockup (lines 187–196) is superseded by this expanded panel layout

## Outside Voice Corrections (incorporated into implementation tasks)
Two design decisions were revised after cross-model review:

1. **Trend arrow requires ≥5 scored sessions** — `computeAlignmentTrajectory` must check that the current 30-day window has ≥5 scored entries before computing slope. Below that threshold: show alignment rate only with "(not enough data for trend)" note. Prevents misleading trend arrows on sparse data.

2. **"Easiest win" top gap** — the "top gap" signal should be the tool present in the user's highest-scored sessions but absent from their recent sessions. Not "most common missing across all sessions" (which nags about tools the user legitimately never needs). Implementation in `computeTopGap()` — see C7.

## Reviewer Concerns (unresolved after 2 spec review iterations)
These are genuine implementation gaps that the eng review or implementation phase should resolve:
- `bannerDismissed` schema: needs a home in `goals.json` structure; `saveGoal()` signature may need a new `saveBannerDismissed()` helper
- `computeAlignmentTrajectory` return shape — specified in `tasks-ceo-review-20260523.md` C6 (AlignmentTrajectory interface)
- "Alignment score" used as sort key for top-3 sessions — defined as `computePersonaAlignment()` return `.score` field
- Vision section describes v2/v3 trajectory; v1 ships only the 4 accepted scope items above
- `--set-persona` may be redundant with existing `goal` subcommand — implementation should evaluate whether a dedicated flag is needed
